# 不写任何注释

在这个项目里，你写的所有代码都不带注释。这条规则优先于你平时"好代码要配注释"的习惯。

## 规则

1. 新写、改写的代码里，不出现任何注释，包括但不限于：
   - `//`、`/* */`、`/** */`（JSDoc、TSDoc、Javadoc）
   - `#`（Python、Shell、YAML、TOML、Dockerfile 等）
   - `"""` 和 `'''` 文档字符串（docstring）
   - `<!-- -->`（HTML、Markdown、JSX 里的 `{/* */}`）
   - `--`（SQL）、`;`（部分配置文件）
   - `TODO`、`FIXME`、`NOTE`、`HACK`、`XXX` 之类的标记
   - 文件头说明、分隔线注释（如 `// ---- 工具函数 ----`）
   - 被注释掉的旧代码（要删就直接删）
2. 需要解释意图时，用清楚的变量名、函数名、类型名表达，必要时把一段逻辑拆成一个名字清楚的小函数。不要靠注释补救。
3. 已有的旧注释：不要顺手去删，也不要跟着模仿它的风格再加新的。只有当整段代码本来就要被删除或重写时，注释才跟着一起消失。
4. 只有一种情况例外：文件格式或工具要求它必须存在才能工作的指令，比如 `#!/usr/bin/env bash`、`"use client"`、`// @ts-expect-error`、`# syntax=docker/dockerfile`、`eslint-disable`。能不用就不用，用了也只写指令本身，后面不要附带解释。
5. 许可证头、`.gitignore` 里的说明行同理：新建时不要加，已有的不动。

## 写完后自查

提交结果之前，对你改过或新建的文件扫一遍：
- 有没有残留的 `//`、`/*`、`#`、`"""`、`<!--`
- 有没有 `TODO` / `FIXME`
- 有没有被注释掉的代码

发现就删掉，再交付。
